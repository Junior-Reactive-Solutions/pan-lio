## 1. MISSION STATEMENT

Rebuild **pan-lio.com** as a fast, accessible, search-visible Next.js website that replaces the current Squarespace build. Pan-Lio Ltd is a Ugandan multi-industry enterprise (real estate, transport, trade, international life insurance, strategic investment) that also operates **Coach DK Global**, the leadership and life-coaching brand of founder **Deo Kateizi**, delivering professional training courses across Uganda, Rwanda and Botswana.

The existing site scored **38/100** in audit. Its design is good; its engineering is not. The rebuild must preserve the established visual identity — warm sand palette, Young Serif display type — while fixing the structural failures the audit identified, above all the fact that **the entire 2026 course catalogue is locked inside five scanned images and is therefore invisible to Google and to screen readers**.

This is a **pitch/demo build first**: it runs locally for client review and is not pointed at live DNS until approved.

### 3.2 The 60:30:10 Rule — Mandatory Per Screen

Every screen must allocate colour as:

- **60% dominant** — `--sand-100` / `--sand-50` surfaces
- **30% secondary** — `--espresso-900` / `--ink-950` structural blocks, dark bands, typography
- **10% accent** — `--sage-600` or `--clay-500` for CTAs, active states, icon highlights, underlines

Use **one accent per screen**, not both, so each page has a clear identity. Document the intended split in a comment at the top of each page component. Alternate dark and light bands down the page for rhythm — this is what makes the ratio read as deliberate rather than accidental.

### 3.3 anime.js v4 — Correct API (critical)

anime.js v4 is a **breaking rewrite** of v3. The old `anime({...})` default export no longer exists. Using v3 syntax will fail silently or throw.

```js
// CORRECT — v4
import { animate, createScope, createTimeline, stagger, onScroll, spring } from 'animejs';

animate('.card', { translateY: [24, 0], opacity: [0, 1], ease: 'out(3)', duration: 700 });
```

```js
// WRONG — v3, do not use
import anime from 'animejs';
anime({ targets: '.card', translateY: 0 });
```

**React/Next.js integration must use `createScope` with cleanup** — this is required for React Strict Mode and unmount safety:

```tsx
'use client';
import { animate, createScope, stagger, onScroll } from 'animejs';
import { useEffect, useRef } from 'react';

export function RevealSection() {
  const root = useRef<HTMLDivElement>(null);
  const scope = useRef<ReturnType<typeof createScope> | null>(null);

  useEffect(() => {
    scope.current = createScope({ root }).add(() => {
      animate('.reveal', {
        translateY: [32, 0],
        opacity: [0, 1],
        delay: stagger(80),
        ease: 'out(3)',
        duration: 800,
        autoplay: onScroll({ enter: 'bottom-=100 top', once: true }),
      });
    });
    return () => scope.current?.revert();   // MANDATORY cleanup
  }, []);

  return <div ref={root}>{/* ... */}</div>;
}
```

**Animation rules — restraint is the brief:**
- Purposeful only: reveal-on-scroll, staggered card entrances, hero headline build, number count-ups, nav state, hover micro-interactions
- Nothing may loop infinitely in the user's peripheral vision
- Nothing may delay content: text is readable with JS disabled
- Animate `transform` and `opacity` only — never `width`, `height`, `top`, `left` (layout thrash)
- Durations 200–800ms; ease `out(3)` / `inOut(2)` / `spring()` for physical elements
- **Every animation must respect `prefers-reduced-motion`** — wrap the whole scope:

```ts
if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;
```

### 3.4 Booking Email

User decision: **email delivery**.

- `app/api/book/route.ts` — a POST Route Handler that validates input server-side (never trust the client), then sends to `coachdk@pan-lio.com`
- Use Resend (simplest) or Nodemailer over Google Workspace SMTP
- Credentials in `.env.local` only — **never commit secrets**; provide `.env.example` with empty keys
- **Graceful degradation:** if no API key is configured (the demo case), the form falls back to a prefilled `mailto:` so the demo is fully clickable with zero setup
- Include: honeypot field + basic rate limit; a clear success and a clear error state
